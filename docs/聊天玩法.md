# FishMatrix Chat 玩法详解

> 把群聊 / 私聊包装成一台可交互的服务器：界面是 SSH 终端，消息是日志。
> 进入群组或私聊后，**直接打字、回车就是发送**，新消息会实时输出。
> 只有连接操作需要命令：`cd` 进群、`ssh` 私聊、`exit` 退出私聊。
> **群聊是临时会话**（不落库、无历史）；**私聊持久化**，二次连接可看历史，
> 并支持发送图片。工具栏“图片”按钮在群聊/私聊中都可发送图片。

## 一、进入聊天

1. 先登录 FishMatrix。未登录访问 `/chat` 会跳转
   `/login?redirect=/chat`。
2. 打开聊天页：测试栈地址为 `http://10.28.13.214:18088/chat`。
3. 页面会自动完成：
   - 用登录 token 换取一次性 WebSocket ticket；
   - 建立实时连接；
   - 加载群组、私聊未读数与当前群在线成员；
   - 默认进入 `dev-group`（研发协作），并开始自动接收新消息。
   - 群聊不加载历史；私聊打开时自动加载最近 20 条。

聊天身份完全来自登录账号，格式为 `u<账号ID>`，昵称与角色来自用户服务。
客户端不能自报身份，也不能覆盖昵称。

## 二、界面说明

### 2.1 顶部栏

| 元素 | 含义 |
|---|---|
| `session: /opt/chat/group/dev-group` | 当前所在“目录”；私聊时显示 `ssh 昵称@节点` |
| 连接状态 | 连接中 / 已连接 / 重连中 / 已断开 |
| `UNREAD n` | 私聊未读总数（群聊为临时会话，不累计未读） |
| 会话 | 展开 / 收起右侧栏 |
| 清屏 | 只清终端画面，不清数据库 |
| 图片 | 选择 PNG/JPEG/GIF/WebP 发送到当前群聊或私聊 |

### 2.2 终端区

提示符会随位置变化：

```text
[甲@dev-node-14 /opt/chat/group/dev-group]$
[甲@dev-node-14 ~]$          # 私聊模式
```

群消息格式：

```text
[10:11:21] [INFO] [dev-group] [#cb213e] 乙@dev-node-02:
发布窗口 22:00，请值班同学确认
```

私聊格式：

```text
[10:12:03] [DM] [#9f31aa] 乙@dev-node-02 -> u1:
在吗？帮我看下告警
```

`#cb213e` 是消息短 ID，撤回时直接使用。

图片消息在终端中只显示占位符，图片本身出现在终端下方的缩略图条中：

```text
[10:13:12] [INFO] [dev-group] [#71ac05] 乙@dev-node-02:
[图片] #71ac05
```

点击缩略图可全屏预览，点右上角“关闭”或遮罩退出。

### 2.3 右侧栏

- **会话组**：群 ID、在线人数、未读徽标；点击等同于 `cd`。
- **在线节点**：全局在线成员，自己会标注 `(you)`；点击等同于 `ssh 昵称`。
- **私聊未读**：最近有未读私聊的节点及条数。
- **脚本**：`funny.cat` / `fish.cat` / `matrix.cat`；点击等同于 `cat`。
- **快捷命令**：最近 50 条、`ps`、`who`、`help`。
- 底部显示当前身份、节点与 ticket 会话信息。

部分皮肤默认收起侧栏，点顶部“会话”即可展开。

## 四、连接与发送

### 4.1 群聊连接：`cd`

```bash
cd dev-group
cd /opt/chat/group/ops-oncall
```

切换后会：

- 同步群内在线成员；
- 重新加入该群并自动接收新消息；
- 群聊是**临时会话**：不加载历史，不写数据库，离线期间的消息不存在，
  也不累计未读、不支持搜索和撤回。

群不存在时返回：

```text
cd: no such file or directory: /opt/chat/group/xxx
```

群组中 `exit` 不会断开连接，只会提示会话常驻。

### 4.2 私聊连接：`ssh`

```bash
who                         # 先看谁在线
ssh 乙                       # 按昵称
ssh 乙@dev-node-02           # 昵称 + 节点精确匹配
ssh u2                       # 按用户 ID
```

- 目标必须在全局在线列表或当前群成员中；
- 不能和自己建立私聊；
- 进入后提示符变成 `~`，顶部显示 `ssh 乙@dev-node-02`；
- 自动加载最近 20 条私聊历史（私聊持久化，二次连接仍可看到）；
- 支持发送图片，图片文件与消息记录都会保存；
- `exit` 结束私聊并回到原群组。

昵称匹配是严格相等。若昵称含不可见字符或重名，优先使用用户 ID
（`who` 表格中的 `u20` 之类）。

对方离线时：

- 消息仍会落库；
- 对方下次连接时服务端补发 `dm_offline`；
- 终端显示“恢复 N 条离线私聊消息”。

### 4.3 发送消息：直接输入

在群组或私聊中直接输入内容，回车即发送：

```text
[甲@dev-node-14 /opt/chat/group/dev-group]$ 今晚 22:00 发布，请确认
```

规则：

- 当前在群组 → 发群消息；当前在私聊 → 发私聊；
- 发送成功后自己的消息由服务端回显到终端；
- 单条最多 2000 字符；
- ANSI 转义、C0/C1 控制字符、双向文本控制符会被清理；
- 默认限流 **20 条 / 10 秒**，超限返回 `RATE_LIMITED`；
- **私聊消息会写入 MySQL**，刷新、重连、换设备后仍在；
- **群聊消息只实时广播，不落库**，刷新或重连后不会保留。

### 4.4 发送图片

1. 点击顶部工具栏“图片”；
2. 选择 PNG / JPEG / GIF / WebP 文件；
3. 图片会出现在终端下方缩略图条，并实时发送给当前会话。

| 场景 | 上限 | 存储方式 |
|---|---|---|
| 私聊 | 5 MB | 文件写入 `CHAT_IMAGE_DIR`，元数据写 `chat_image` 表，消息只存图片 ID；二次连接可加载 |
| 群聊 | 1 MB | 以 data URL 经 WebSocket 实时广播，不落盘、不落库；刷新即消失 |

私聊图片读取需要鉴权：上传者本人，或该私聊消息的参与者才能访问。
终端里只显示 `[图片] #短ID`，不会把 data URL 或图片 ID 打印出来。

**命令词开头的消息：**

以 `cd `、`ssh `、`grep `、`recall ` 开头的文本会优先按命令解析。
`who`、`ps`、`help`、`ls`、`tail` 只有完整命令形式才生效，因此
`who are you?`、`ps 我错了`、`help me` 会正常作为消息发送。
`cat` 只有跟已知脚本名时才作为命令。

## 五、辅助命令

### 5.1 `ls`：查看群组

```bash
ls
ls /opt/chat/group
```

```text
total 3
drwxr-xr-x ... dev-group      研发协作 (2 online)
drwxr-xr-x ... ops-oncall     运维值班 (1 online)
drwxr-xr-x ... tech-share     技术分享 (0 online)
```

### 5.2 `tail`：查看私聊历史

```bash
tail -n 20 chat.log     # 最近 20 条
tail -n 100 chat.log    # 最多 200 条
tail chat.log           # 默认最近 20 条
```

`tail` 只对私聊有效；群聊为临时会话，执行后会提示不保存历史。
私聊中的新消息会自动输出，不需要 `tail -f`。
为了兼容旧习惯，`tail -f chat.log` 仍可执行，但等价于加载最近 20 条。

### 5.3 `ps`：当前群在线进程

```bash
ps
ps aux | grep dev
```

显示当前群在线成员。PID、CPU、MEM 等为舞台化数值，成员与节点是真实在线数据。

### 5.4 `who`：全局在线节点

```bash
who
```

```text
USER       NODE          UID       STATUS
甲         dev-node-14   u1        online (you)
乙         dev-node-02   u2        online
```

侧栏“在线节点”使用同一数据，每 30 秒刷新一次。

### 5.5 `grep`：搜索消息

```bash
grep "发布"
grep "build passed"
grep "100%"
```

- 只在当前私聊中搜索；群聊为临时会话，执行后会提示不可搜索；
- 返回最近最多 50 条匹配消息，带完整消息头与短 ID；
- 关键字按字面匹配，`%`、`_` 不会被当作 SQL 通配符；
- 已撤回的消息不会出现在结果中。

### 5.6 `recall`：撤回消息

先看消息头里的短 ID：

```text
[10:11:21] [INFO] [dev-group] [#cb213e] 甲@dev-node-14:
```

然后执行：

```bash
recall #cb213e
recall cb213e
recall 完整UUID
```

规则：

- 仅支持私聊消息撤回；群聊为临时会话，不支持撤回；
- 只能撤回自己的消息；
- 默认窗口 **120 秒**，超时报错；
- 撤回后内容清空，历史显示“该消息已撤回”；
- 对方会实时收到撤回提示；
- 短 ID 只映射当前终端会话中见过的消息（最多保留 500 条）；更早的消息
  需要使用完整 UUID。

### 5.7 `cat`：广播 ASCII 脚本

```bash
cat ascii/funny.cat
cat ascii/fish.cat
cat ascii/matrix.cat
```

将 ASCII 艺术图以 `ascii` 类型发送到当前群或当前私聊，接收方按代码块样式展示。

### 5.8 其他

```bash
pwd       # 当前路径；私聊时为 /home/dev
clear     # 清屏
cls       # 同 clear
help      # 命令说明
exit      # 私聊中退出私聊；群组中仅提示会话常驻
logout    # 同 exit，不会退出登录账号
```

## 六、未读与已读

- **私聊未读**：侧栏“私聊未读”区域与顶部 `UNREAD n`。
- **群聊没有未读**：群消息只在当前群实时显示，离开会话即不再接收/累计。
- 当前所在私聊的新消息会实时打印，并自动标记已读。
- 打开私聊、在当前私聊中收到消息、重连补拉完成后都会标记已读。
- 不在当前私聊时，新私聊只累计未读，不打断当前终端。
- 收到私聊但未打开会话时，会打印提示：

```text
[INFO] 乙@dev-node-02 发来私聊，输入 ssh 乙 打开会话
[10:12:03] [DM] [#9f31aa] ...
```

已读位点保存在 MySQL 的 `chat_read_state`，刷新页面后未读状态保持一致。

## 七、断线重连与持久化

- **私聊持久化**：页面刷新、网络断开、服务重启后，历史从 MySQL 读取，不丢消息；
  图片文件保存在 `CHAT_IMAGE_DIR` 卷中，二次连接仍可加载。
- **群聊临时化**：消息与群聊图片都只实时广播，不写数据库/磁盘；刷新、重连或
  离线期间不会保留。
- WebSocket 重连时重新申请一次性 ticket，不需要重新登录。
- 私聊重连后按最后看到的 `seq` 自动补拉断线期间的消息，并按消息 ID 去重：

```text
[INFO] 重连补拉完成
```

- 离线期间收到的私聊会在连接建立时补发（含图片消息，图片按需重新拉取）。
- 私聊历史分页、搜索、撤回状态均以 MySQL 为准。
- 登录失效时停止重连，清理本地登录态并跳回 `/login?redirect=/chat`。

## 八、双人体验流程

准备两个已审批账号，分别用普通窗口与隐身窗口登录测试栈。

**窗口 A：**

```bash
cd dev-group
```

**窗口 B：**

```bash
cd dev-group
终端联调开始，收到请回复
```

A 的终端会实时出现这条消息，不需要任何“跟随”命令。群聊消息是临时的，
刷新或重连后不会保留。接着：

**窗口 A：**

```text
收到，链路正常
```

```bash
who
```

**窗口 B：**

```bash
ssh A的昵称
私聊通道也正常
```

点击工具栏“图片”发送一张小于 5MB 的图片；A 的缩略图条会出现该图，
点击可全屏预览。随后：

```bash
tail -n 20 chat.log
grep "私聊通道"
exit
```

**窗口 A：**

```bash
recall #刚发出的私聊消息短ID
```

刷新页面重新进入 `/chat`：群聊为空（临时会话），私聊历史、图片、
撤回状态与未读数应保持一致。群聊中发送图片只会在双方在线时显示，
刷新后消失。

## 九、当前边界

已支持：

- 群聊（临时会话，实时广播、不落库）；
- 私聊（持久化，二次连接可看历史）；
- 直接输入发送、自动实时接收；
- 私聊 MySQL 历史持久化与游标分页；
- 私聊关键字搜索、消息撤回；
- 私聊未读 / 已读；
- 图片发送：私聊落盘 + 元数据持久化，群聊 data URL 实时转发；
- 图片缩略图条与全屏预览；
- 全局在线列表与群内在线成员；
- 离线私聊补发；
- 断线自动补拉与幂等发送；
- 发送限流与终端内容清理；
- 一次性 WebSocket ticket。

暂不支持：

- 群聊历史、群聊图片持久化、群聊未读、群聊搜索/撤回；
- 文件、语音；
- 消息编辑、引用回复、表情回应；
- 群组创建与成员权限管理；
- 多端已读回执 UI；
- 全文索引（Elasticsearch）；
- 迁移旧版 Redis Stream 历史（历史以 MySQL 为准）。

## 十、常见问题

**Q：直接打字回车就能发消息吗？**
A：可以。当前在群里就发群消息，在私聊里就发私聊。`echo "...">> chat.log`
仍兼容，但不再需要。

**Q：为什么我发的消息没有出现？**
A：检查顶部连接状态是否为“已连接”，以及是否触发 `RATE_LIMITED`。
消息会被服务端回显，通常在一瞬间完成。

**Q：群里别人发消息为什么看不到？**
A：群聊是临时会话，只在当前群实时显示。若你正在私聊或其他群，该消息
不会被保存，也不会累计未读；切回群组后只能看到之后的新消息。

**Q：图片能保存吗？**
A：私聊图片会保存（文件 + `chat_image` 元数据），二次连接可在历史中重新加载；
群聊图片只实时广播，刷新或重连后消失。私聊上限 5MB，群聊上限 1MB。

**Q：为什么有些话被当成命令了？**
A：以 `cd `、`ssh `、`grep `、`recall ` 开头的文本会优先按命令解析。
如果只是想发这类内容，可加标点或换一种说法。

**Q：为什么 `ssh` 找不到对方？**
A：目标必须当前在线，或在当前群成员列表中。可先执行 `who` 确认，
优先使用 `who` 表格中的用户 ID，例如 `ssh u20`。

**Q：发送太快会发生什么？**
A：默认 20 条 / 10 秒，超出后终端显示 `RATE_LIMITED`，稍等再发即可。

**Q：消息里的颜色控制符会生效吗？**
A：不会。服务端与前端都会清理控制字符，避免终端注入。

**Q：断线后消息会丢吗？**
A：私聊不会：消息先落 MySQL，重连后按游标补拉，离线私聊消息单独补发。
群聊会丢：临时会话只在在线连接间转发，断线期间的消息不会保留。

**Q：退出登录后聊天连接还在吗？**
A：登录失效会触发鉴权失败，前端停止重连、清理登录态并跳转登录页。
服务端鉴权缓存最长 60 秒。

## 附录：默认参数

| 项目 | 默认值 |
|---|---|
| WebSocket ticket 有效期 | 60 秒，一次性 |
| 鉴权结果缓存 | 60 秒 |
| 发送限流 | 20 条 / 10 秒 |
| 单条消息上限 | 2000 字符 |
| 私聊图片上限 | 5 MB（`CHAT_MAX_IMAGE_BYTES`） |
| 群聊图片上限 | 1 MB（`CHAT_MAX_GROUP_IMAGE_BYTES`） |
| 图片存储目录 | `CHAT_IMAGE_DIR`，默认 `./data/chat-images` |
| 撤回窗口 | 120 秒（仅私聊） |
| 私聊历史单页上限 | 200 条 |
| 搜索单次上限 | 50 条（接口上限 100） |
| 在线状态 TTL | 60 秒，心跳 25 秒 |
| 默认群组 | `dev-group`、`ops-oncall`、`tech-share` |
